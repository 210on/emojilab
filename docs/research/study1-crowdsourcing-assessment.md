# Study 1 クラウド募集と倫理審査の照合

記録日: 2026-10-28

状態: 調査・設計案。募集・データ収集・変更申請は未実施。

## 1. 今回の問い

Yahoo!クラウドソーシングなどで約100人を募集し、EmojiLab.の暫定スコアと人間による評価の対応、個別のデザイン要因の影響を調べられるか検討する。

**結論:** 限られた要因を対象としたオンライン評価は設計できる。ただし100人は十分な検出力を保証せず、申請書と異なる募集・人数・謝礼・設問等について、調査開始前に研究責任者・所属機関へ必要な変更手続きを確認する。以下は承認済み手続きと断定しない。

## 2. 添付資料の位置づけ

- 2026年6月24日付の研究倫理審査申請書・実施計画書・説明文・質問項目・刺激概要を確認した。承認通知や最新版としての適用範囲は、この文書単体では確認できない。
- 変更願のWord文書は、変更前・変更後と理由を記載する**未記入の様式**であり、提出・受理済みの変更届を示すものではない。
- 倫理指摘事項PDFは、複数の審査案件に共通する指摘のまとめであり、本研究への個別指摘や承認通知と断定できない。募集、所要時間、同意、データの識別と撤回、保存等の不整合に注意する資料として参照する。
- 原本には氏名・連絡先・研究環境等の情報が含まれるため、公開リポジトリへ原本を置かない。

## 4. 15刺激・100人を使う比較例

以下は**計算例**であり、要因・語句・配色・効果量・参加者数を決定したものではない。申請書上の「15点」が全体の画像数を意味するか、1人当たりの提示数として複数版が認められるかを含め、実際の刺激構成を事前に相談する。

1. 比較したい項目を例えば3つに絞り、各項目について5語句を選ぶ。例: 内側線の有無、横幅の変形、フォントウェイト。ただしこの選択は仮であり、各要因の2水準と固定条件を先に定義する。
2. 同じ語句を元に、その比較項目のみを変更した2画像を用意する。実際には操作に伴い輪郭面積・字形なども変化しうるため、同時に変わった見た目を記録し、評価を「該当操作の効果」として解釈する。
3. 参加者を2つの提示リストに均等に割り当て、1人には各語句を1回、計15点だけ提示する。リストBでは、各語句の提示画像をリストAと反対の水準にする。同じ語句の2版を同一参加者に見せない。
4. 両リストに各比較項目の両水準が入るよう、語句ごとにA/Bの割当を反転する。全員に同じ方向の水準が偏らないこと、画像ごとの人数、提示順、語句と水準の対応を実行前に監査する。
5. 各画像は、申請書の記載に沿って同じ32 CSS px画像をライト・ダーク背景に並べる。評価を1組に対して取得するなら、明背景と暗背景それぞれの効果は分離できず、**2背景を並列で見た条件**として解釈する。

完了100人・各15点なら、最大1,500件の刺激評価。各比較項目は5語句×100人＝最大500件で、各語句の2画像はそれぞれ約50評価を得る計算になる。しかし500件は独立した500人でも500語句でもない。人数、語句数、参加者間・語句間の差、相互作用、欠測と天井・床効果が推定精度を制約する。5語句だけの比較から全日本語語句へ一般化することはできず、100人の検出力は未検証。

各語句が特定の要因にだけ割り当てられる場合、要因間の絶対的な影響度を、語句差を無視して比較できない。要因別の比較群に文字数、文字種、画数、馴染みなどを均衡させ、語句と要因の割付を別リストで入れ替える設計も候補とするが、必要な刺激画像数と倫理書類との関係、参加者負担を先に確認する。

## 5. 測定・分析上の注意

- 主観的な「見やすさ」は申請書にある主要な評価候補だが、読み取りの客観的正答とは別物である。意味自由記述の一致率を分析する場合は採点基準を事前に決め、条件を伏せた採点・複数評価者の一致と判断困難例を扱う。
- 文字転記を主要指標にしたい場合は、現行申請の質問項目との差分を確認し、必要な変更手続きを行う。画面に文字を残したまま読ませる場合、再確認・語の推測・IMEの影響も含む。
- 同一参加者が複数画像を、同一語句が複数参加者に評価されるため、参加者と語句の繰り返しを考慮した混合効果モデル等を検討する。モデル・主効果・交互作用・欠測・順序・除外基準・複数比較を事前に決め、推定値と信頼区間を報告する。
- 色、線、フォント、文字数、画数など、変数をすべて一括投入した係数を独立した因果効果とみなさない。画数は語句そのものと結び付くため、語の頻度や文字種の違いとの分離も必要。
- 暫定スコアの検証では、データ取得前のスコア版と刺激を固定する。同じデータで調整した新しい重みを同じデータで検証すると過大評価しうる。改訂は探索的に扱い、参加者・語句の単位を踏まえた別データまたは検証設計を設ける。
- 参加者の端末・視距離・表示倍率・周囲の明るさ・視力・入力方法の違いは避けきれない。申請・同意の範囲内で必要な環境情報を確認し、一般化の限界を記載する。
- 見やすいデザインが常に正解・高スコアと仮定しない。色の印象・表現性も含む評価は別の研究課題として分ける。

## 6. 募集サービスの確認

Yahoo!クラウドソーシングの[依頼者向け案内](https://crowdsourcing.yahoo.co.jp/special/owner/what)では法人・個人事業主向けの依頼窓口、アンケート、設問数や料金等が案内されている。大学・学生個人の契約可否、現在の料金、15刺激×複数設問に対応する表示方法、参加者ごとのランダム割付、完了コード、重複防止、撤回、PC限定、外部サイト利用とデータ保存については、契約前に事業者へ直接確認する。

同サービスには[外部サイトで調査して完了キーワードを入力する公開募集例](https://crowdsourcing.yahoo.co.jp/request/detail/3589519072)があるが、個別案件の存在だけで今回の方式の利用条件や許可を断定しない。現行の研究プロトタイプはlocalStorage・手動ダウンロード方式であり、回答の自動回収、研究者による削除、撤回用IDと報酬の照合を実現する設計は確認されていない。

費用は、事業者への基本料金・謝礼・手数料・税、予備実験、途中中止・対象外者への支払い、無効回答、追加募集を分けて見積もる。謝礼額や途中中止時の支払いは、参加者に過度な圧力を与えず、正答率と支払いを結び付けない方針を含め、所属機関と事業者に確認する。

## 7. 次の確認

1. 実際の承認通知、適用中の申請書、変更届とその承認状況を確認する。
2. 指導教員・倫理審査窓口へ、人数、募集・謝礼、刺激版数、評価項目、回収・撤回方法の変更案を照会する。
3. Yahoo!側へ、契約主体・外部調査・割付・対象端末・データと料金の仕様を照会する。
4. 認知心理学・統計の専門家と、主要比較を絞り、15刺激×複数リストの情報量と必要な人数をシミュレーションする。
5. 小規模の手順テストで所要時間、表示、完了率、条件割付、回答とデータ回収を確認する。実施は承認範囲を確認した後とする。
