## 試作の流れ

1. 仮の参加案内と試作確認
2. PC使用とブラウザ表示倍率100%の自己確認。倍率の自動判定はしない
3. 暫定的な参加条件の確認
4. 15画面で32 CSS pxの絵文字を明暗背景に並べて表示し、三つの7件法と任意の自由記述を試す。回答の省略も可能
5. 保存・送信されないことを明記した試作完了画面、または途中中止

表示する15語は申請書に記載された候補から作った仮の刺激である。初版v0.1では全て同じデザイン設定だったが、v0.2では色×線の仮4条件を4リストで確認できるようにした。確認用の提示順は固定シードであり、本番の参加者用の無作為化・サーバー割付は未実装である。画像はブラウザ内で生成しており、実験用に固定・検証した刺激画像ではない。

## 本番前に決めること

2026-10-28更新: 次段階の第一候補を[色×黒内側線の予備調査案](./study1-prepilot-plan.md)に具体化し、[参加説明・同意の草案](./study1-consent-draft.md)を用意した。ローカル試作v0.2では4つの割付リストを研究者が選んで内容を確認できる。v0.1の全刺激同一設定から色×線の仮4条件へ変更したが、画像固定や実参加者の無作為割付は未実装であり、本番募集禁止は変わらない。

- 倫理審査の承認済み版を確認する。申請資料の参加人数、募集方法・謝礼、手続き、保存先、撤回方法との相違は、指導教員と倫理審査窓口に確認し、必要な変更承認を得る。試作の文言や参加条件は承認済みの説明文ではない
- 募集ページ、同意書、質問項目、所要時間、参加資格、謝礼条件、途中終了、問い合わせ先を確定する。完了コード発行と謝礼の条件は撤回権と矛盾しないよう確認する
- 主目的と主要アウトカム、要因、水準、操作の仕方、文字・背景・順序、割付、除外規則、分析モデルを事前に決める。参加者100人という人数だけでは個々の効果の精度は保証されず、各条件の提示回数・参加者内相関を含むシミュレーションや予備調査で見積もる
- 意味理解や自由記述は文脈や既知の語による推測の影響を受ける。視覚的な判読と意味の推測を区別し、正誤を使う場合は回答方法、採点規則、候補提示の有無を別途設計する。自己評価だけから判読精度や因果効果を断定しない
- CSS pxは物理サイズではない。ズームの自己確認は物理的大きさ、OSスケーリング、画面密度、視距離を統一しない。記録する環境情報の必要性とプライバシーを確認し、端末や環境差は限界として扱う
- フォント・レンダリング・表示サイズ・背景・画像内容を固定し、生成元設定と画像ハッシュを記録する。読込失敗、表示崩れ、配列、提示順、回答飛ばしを検証する

## 保存・完了・撤回の設計課題

- 研究室で管理する専用プロジェクトを選定する。開発環境と本番環境を分離し、最小限のデータだけを保存する。管理者・閲覧権限・保存期間・バックアップやログの扱いも大学の規程と倫理承認に合わせる
- 公開ブラウザに管理用秘密鍵を置かない。参加者からは必要な操作だけを許可し、他人の回答の閲覧・変更を禁止する。サーバー側で入力検証・アクセス制御を行い、権限設定を独立にテストする
- 重複送信や通信中断への対応、提出完了の確実な判定、完了コードの推測・再利用対策、回答とコードの紐付け範囲を設計する。送信失敗時に完了と表示しない
- 参加者が撤回できる期間と手順、本人からの照会方法、対応できない匿名化後の制約を明記する。照会用情報が必要な場合は収集前に倫理面と安全な管理方法を確認する
- 募集から回答、再読み込み、通信エラー、途中終了、完了コード入力、撤回までを、テスト用環境で模擬確認する。実参加者データは承認・安全確認前に収集しない
