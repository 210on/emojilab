# Study 1 表示環境チェックの検討

作成日: 2026-10-28

状態: 設計案。参加者向けのチェックは未実装。収集項目、手順、承認内容の照合が必要。

## 1. 調査で揃えるもの

研究者の目的は、SlackやDiscordの小さな絵文字表示を想定し、画像を一定の正方形の枠に収めて比較することである。2026年6月24日付の申請書では、実験1の各刺激を32×32 CSS px、ライト・ダーク背景に並列表示、PC、ブラウザ倍率100%と記載している。実際のサービスではリアクション、文章中、単独投稿、端末などで表示サイズや処理が異なりうるため、実験上の32 CSS pxを両サービスのすべての場面における実測値と主張しない。

[Slackの公式ヘルプ](https://slack.com/help/articles/206870177-Add-custom-emoji-and-aliases-to-your-workspace)は正方形・透明背景の画像を推奨している。[Discordの公式ヘルプ](https://support.discord.com/hc/en-us/articles/360036479811-How-to-Add-Custom-Emojis-on-Discord)はアップロード条件や編集機能を説明している。これらの記載のみでは、長方形画像があらゆる表示箇所で必ずどのように縮小・正方形化されるか、各箇所の現在の表示寸法まで確定できない。実測には対象の日時・アプリ・画面・投稿形式・ズーム等を記録する。

画像全体が同じ正方形表示枠に収まっても、文字の占める領域は配置・透明余白・縁線・正規化の方法で変わる。実験では枠、画像の生成・縮小方法、各刺激の実寸や透明余白を記録し、文字の縮小率を推測で決めない。

## 2. ブラウザの倍率をどこまで確認できるか

- 通常のWebページには、OS設定、画面のピクセル密度、個別ディスプレイをまたいで「ブラウザのページ倍率が確実に100%」と判定できる標準的な方法はない。
- [`window.devicePixelRatio`](https://developer.mozilla.org/en-US/docs/Web/API/Window/devicePixelRatio)はページズームで変化するブラウザがある一方、画面の密度やOS側の拡大率の影響も受ける。値が1だから100%、2だから200%とは判断できない。開始時の値だけから実際のページズーム率は復元できない。
- [`visualViewport.scale`](https://developer.mozilla.org/en-US/docs/Web/API/VisualViewport/scale)はピンチズームの尺度であり、通常のページズームを一般的に判定する値ではない。値が1でもページズーム100%は保証できない。APIの利用可否と挙動は端末・ブラウザで異なる。
- CSS要素の`getBoundingClientRect()`などで画像の幅・高さをCSS pxとして検査すれば、指定寸法・レイアウト崩れを確認できる。ただし、これもページズームの絶対値、画像の物理寸法や視距離を保証しない。
- PC・ブラウザ・DPR・表示範囲の情報は、事前説明と倫理審査の範囲を確認したうえで、必要最小限を記録する。正確性が不明な自動判定だけで参加者を除外しない。

## 3. 提案する事前チェック

1. 募集側で可能ならPCに限定し、実験開始前に参加者へPC利用を確認する。自動端末判定は補助情報として扱う。
2. 「ブラウザのメニューで表示倍率を100%にしてください」と案内する。macOSは`⌘+0`、Windowsは一般に`Ctrl+0`で倍率をリセットできるブラウザが多いが、個別設定やブラウザの既定倍率によってはリセットだけで100%と限らない。メニューでの確認を併記する。
3. 「100%を確認しました」という本人確認を行う。変更できない人への参加・中止・謝礼の案内は、承認された条件に沿って決める。OSの表示倍率やアクセシビリティ設定を勝手に変更させる設計にはしない。
4. 画像を32×32 CSS pxで明暗背景に表示し、画像要素のCSS上の寸法と読み込み状態を検査する。試験刺激を読めたかどうかを、研究に必要な適格条件と混同しない。申請書の表示確認との整合を検討する。
5. 本人確認後、DPRやviewportに変化が起きた場合は、ズーム変更、別画面への移動、ウィンドウ変更などの可能性として「表示設定をもう一度確認してください」と案内する。DPRの変化はズーム変更の確証ではない。ページ開始前にすでに100%以外だった場合も見抜けない。未対応ブラウザでは「検知不可」とし、検知結果を正確な倍率として表示しない。
6. 倍率の絶対値をシステムが確認できた、またはすべての参加者の物理サイズが揃ったと記録・主張しない。参加者の確認、CSS寸法の実測、環境変化の有無はそれぞれ分けて扱う。

スクリーンショット・画面写真、ブラウザ拡張機能、画面共有やカメラの許可は、この案では要求しない。必要になった場合は、取得内容・目的・保存・削除・同意と倫理審査を別途確認する。

## 4. 実装・検証前の確認

- 申請済みの15刺激、32 CSS px、明暗背景並列、質問、対象者、撤回、保存と、調査画面の実装が一致すること。
- 未確認の本番条件・同意文面・サーバー回収・完了コードを完成済みと扱わないこと。現在のStudy 1はlocalStorageを使う試作であり、参加者の回答を研究者へ自動送信しない。
- Chrome・Edge・Safari等で、ズーム前／本人が100%確認後／途中変更／別ディスプレイ移動／未対応API時を合成データで確認すること。実際に検知できた範囲を報告すること。
- 本人確認と補助的な環境情報は、どこに保存するか、必要か、保存期間・撤回の扱いを研究責任者と事前に決めること。
- 設定を変更できない参加者の扱い、表示確認による選抜バイアス、低視力やアクセシビリティへの配慮を事前に検討すること。
